# BOOM 4 Tray

**在 Windows 托盘中控制两台 Ultimate Ears BOOM 4，直接开启 PartyUp、调音量和切换左右声道。** 不用每次先打开手机 App 建组。

版本：**v0.1.0-alpha** · Windows x64 · 中文界面

[下载 Windows 便携版](https://github.com/MultiplyTen/boom4-tray/releases) · [English](docs/README.en.md) · [验证记录](docs/TESTING.md) · [更新说明](docs/RELEASE_NOTES.md)

本项目独立开发，与 Logitech／Ultimate Ears 无隶属关系。两台 BOOM 4 已完成电脑组队、左右分离和交换左右的实机试听验证；这是初期公开版，其他设备组合与固件仍需验证。

## 能做什么

- 从 Windows 已配对设备中选择主音箱和副音箱，开启、结束 PartyUp。
- 读取主音箱的组队状态、电量和音量；调整主音箱音量、发送组队音量同步指令。
- 切换完整声音同播、主左／副右、主右／副左三种模式。
- 播放内置的八秒左右声道测试音，检查实际发声位置。
- 关闭窗口后留在托盘，通过右键菜单继续控制。退出工具保留当前音乐播放。

音频仍由 Windows 通过蓝牙发送给**主音箱**，再由音箱分发 PartyUp 音频。工具发送控制指令，不会把电脑音频复制到两个独立输出。

## 下载与安装

1. 打开 [Releases（含 Alpha）](https://github.com/MultiplyTen/boom4-tray/releases)，下载 **`BOOM4-Tray-Windows-x64.zip`**。普通使用请选择这个便携包，无需安装 Python。
2. 将 ZIP **完整解压**到一个固定文件夹。保留 `BOOM4-Tray.exe` 与 `_internal` 文件夹的相对位置，不要只复制 EXE，也不要直接在压缩包内运行。
3. 双击 `BOOM4-Tray.exe`。无需安装服务、无需管理员权限；不会自动加入开机启动。

首次发布版未进行代码签名。请从本仓库的 Releases 获取成品；也可以按下文从源码运行。

## 首次配对与开启 PartyUp

1. 打开两台音箱，在 Windows「设置 → 蓝牙和设备」中**分别完成配对**。主音箱需要建立音频连接；副音箱只需保留配对记录，不必作为第二个音频输出。
2. 暂时关闭手机蓝牙，或确保手机 UE App 已释放音箱控制连接。
3. 打开工具，点击「刷新设备」，分别选择主、副音箱。主音箱是电脑要播放到的那台；两台名称相同时，可用名称后面的短标识区分。
4. 点击「刷新状态」，然后点击「开启 PartyUp」。等待本次操作完成后再继续。
5. 在 Windows 任务栏的声音输出菜单中选择**同一台主音箱**，播放音乐，确认两台都发声。

工具不会替你切换 Windows 声音输出。启动时也不会自动组队或开始播放音乐。

点击「结束 PartyUp」会结束主音箱广播，并尝试移除所选副音箱。开启、结束或切换声道时，播放可能短暂停顿。

## 音量与托盘操作

| 操作 | 用法 |
| --- | --- |
| 读取电量／音量 | 选择主音箱，点击「刷新状态」。显示的是主音箱信息。 |
| 调整音量 | 刷新成功后拖动滑条，点击「应用音量」。修改后会回读主音箱确认。 |
| 同步两台音量 | PartyUp 开启后点击「同步两台音量」，发送组队音量同步指令。实际响度请试听。 |
| 托盘快捷操作 | 右键图标，可开启／结束 PartyUp、选择声道、音量加减、刷新状态。 |
| 收起／退出 | 关闭窗口会收进托盘；从托盘选择「退出工具（保留播放）」才会退出。 |

读取状态时只主动连接主音箱，避免在组队播放中直接查询副音箱造成干扰。状态或写入结果未知时会显示「未确认」；主音箱报告了成员，也不能代替实际试听。

## 三种声道模式

先开启 PartyUp，再进入「声道（实验）」页面选择模式并点击「应用声道」。也可以从托盘的声道子菜单切换。

| 界面选项 | 预期播放方式 |
| --- | --- |
| 同播（完整声音） | 两台均播放完整内容，适合分散摆放。 |
| 左右立体声（主左／副右） | 主音箱播放左声道，副音箱播放右声道。 |
| 交换左右（主右／副左） | 主音箱播放右声道，副音箱播放左声道，无需搬动音箱。 |

本次两台 BOOM 4 的左右分离与交换已由实际试听确认。页面仍保留「实验」标记，因为尚未覆盖不同固件、其他型号及长期使用情况。副音箱指令回复不等于声道分离的声学证明，首次使用请做以下测试。

### 用内置测试音确认

1. 先把音量调低，在 Windows 声音输出中选择主音箱。
2. 到 Windows「设置 → 辅助功能 → 音频」，关闭「单声道音频」。Windows 10 中相应选项位于「轻松使用 → 音频」。
3. 应用「左右立体声（主左／副右）」，点击「播放左右测试音」。可随时点击「停止测试音」。
4. **先左声道一秒低音 → 静音一秒 → 右声道一秒高音 → 静音一秒，重复一次。** 总长八秒。应先只有主音箱响，再只有副音箱响。
5. 应用「交换左右（主右／副左）」并重复测试，应先副音箱响，再主音箱响。恢复「同播（完整声音）」后，两台应均可播放两次提示音。

如果左右两次提示都从两台一起发声，不应视为立体声切换成功。先检查 Windows 单声道设置、主音箱选择和实际应用的模式。

测试文件为 48 kHz、16 位双声道 PCM：左声道 440 Hz、右声道 660 Hz，带 50 ms 淡入淡出，峰值约 −18 dBFS。最终听感响度仍取决于电脑和音箱音量。

## 兼容性与已知限制

| 范围 | 当前状态 |
| --- | --- |
| Windows 11 x64 ＋两台 BOOM 4 | 已验证电脑 PartyUp 播放；主左／副右及交换左右均通过用户试听。 |
| 其他 BOOM 4 固件／蓝牙适配器 | 未覆盖，不保证与本次结果一致。 |
| Windows 10 x64 | 代码面向 Windows 10／11；本次未在 Windows 10 实机验证。 |
| MEGABOOM 4 | 可出现在设备选择中，但未完成本工具的实机验证。 |
| 其他 UE 型号、混合组队、三台以上 | 不属于本版验证范围；本工具界面只面向两台设备。 |

没有测量声道串扰、两台同步误差或音视频延迟。本版没有视频／游戏延迟补偿，不提供固件升级、恢复出厂、EQ、远程开机或环绕声功能。固件维护请使用官方手机 App。

软件检查和实机试听分别记录在 [docs/TESTING.md](docs/TESTING.md)。不要把自动化测试通过理解为所有音箱兼容。

## 故障排查

| 现象 | 建议检查 |
| --- | --- |
| 只找到一台／没有设备 | 确认两台均已在 Windows 分别配对，再点「刷新设备」。当前版本按蓝牙名称识别 BOOM 4／MEGABOOM 4，自定义名称不含型号时可能无法显示。 |
| 连接超时、音箱不回复 | 保持音箱开机，关闭手机 UE App 或暂时关闭手机蓝牙。等片刻后刷新状态，避免快速连续断开重连。 |
| 显示已开启，但只一台响 | 检查 Windows 音频输出是否为所选主音箱；确认副音箱已开机且在范围内，再刷新状态、试听。 |
| 提示已有组队但成员未确认 | 先刷新状态。必要时显式点击「结束 PartyUp」，等操作完成，再开启；不要连续重复点击开启。 |
| 左右都从同一台／两台一起响 | 关闭 Windows「单声道音频」，核对模式和主、副选择，用内置测试音确认。 |
| 切换声道未完全确认 | 可能已有部分设置生效。先刷新状态；需要恢复时选择「同播（完整声音）」并应用，再试听。 |
| 音量滑条不可用 | 先选择主音箱并成功刷新状态。结果未知时，工具会禁用继续调节，等待重新读取。 |
| 关闭窗口后找不到 | 查看任务栏的隐藏图标区域，右键 BOOM 4 图标打开面板。再次启动也会尝试显示现有窗口。 |

暂时无法从电脑直接建组时，还可尝试：手机 App 建立 PartyUp，保持两台开机且不点「结束派对」，断开手机音频连接，再让 Windows 连接同一台主音箱播放。这个方法也已在本次两台设备上验证。

提交问题时，请描述系统版本、音箱型号、固件版本（如已知）、操作步骤及实际听到的结果。请遮住截图中的设备短标识，并删除完整蓝牙地址、个人设备名、本机用户名与个人文件路径；无需上传原始蓝牙数据。

## 隐私与本地数据

运行工具不需要账户，不使用云服务，不上传诊断信息，没有遥测、自动更新或远程控制服务。

主、副音箱选择仅保存在当前用户的 `%LOCALAPPDATA%\Boom4Tray\selection.json`，其中包含用于连接的设备地址。该文件属于本地设置，不随便携包分发，也不应提交到公开仓库。删除工具文件不会自动删除这个选择记录；如需清除，可在工具退出后删除该文件。

开发阶段的 `hardware-status.json`、本地日志、设备配置与原始捕获不包含在发布包中，并已通过 `.gitignore` 排除。

## 从源码运行与构建

需要 Windows x64、Python 3.13（包含 Tkinter），以及可用的蓝牙适配器。下载仓库完整源码并解压，在项目文件夹运行：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe boom_tray.py
```

源码目录中的 `启动托盘.cmd` 会优先启动已打包的便携版，否则用 `.venv` 中的 `pythonw.exe` 隐藏控制台启动。

```powershell
# 自动化检查：不操作真实音箱
.venv\Scripts\python.exe -m unittest discover -s tests -v

# 检查界面与 Windows 运行依赖：不查询蓝牙、不播放音频
.venv\Scripts\python.exe boom_tray.py --smoke

# 重建测试音：只写 WAV
.venv\Scripts\python.exe tools\create_channel_test.py

# 构建便携版；依赖已在上面安装
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

输出为 `dist\BOOM4-Tray\BOOM4-Tray.exe` 和 `dist\BOOM4-Tray-Windows-x64.zip`。`build.ps1` 会检查源码语法、源码与成品的 smoke 流程；这些检查不会替代实机试听。
